# docseed の文書

docseed の文書は、**読む人ごと**に分けています。自分に合う入口から読んでください。

| 読む人 | 入口 | 内容 |
|---|---|---|
| 使う人（ファイルを置く・探す・共有する） | [利用者ガイド](user/README.md) | 画面の使い方。ブラウザとスマホでの操作 |
| サーバーを置く人・管理する人 | [管理者ガイド](admin/README.md) | 導入、HTTPS、公開、任意の機能の有効化、バックアップ、監視、更新、困ったとき |
| コードを直す人・機能を足す人 | [開発者ガイド](dev/README.md) | 開発環境、テスト、コードの地図、**文書の書き方と更新の手順** |
| 仕組みを知りたい人 | [設計書](design.md) | なぜそう作ったか。データモデル・パイプライン・検索・安全策・API・画面・配置 |
| 経緯を知りたい人 | `research/` | モデルの調査と Pi 5 での計測（[OCR・埋め込み](research/ocr-embedding-models.md)、[Phase 0 の計測](research/phase0-results.md)、[新機能の調査](research/new-features.md)） |

## 文書の種類と置き場所

| 場所 | 種類 | 書き方 |
|---|---|---|
| `docs/user/` | 利用者ガイド | **画面の言葉**で書く。`.env` やコマンドは出さない（管理者ガイドへのリンクにする） |
| `docs/admin/` | 管理者ガイド | 手順はコピーして実行できるコマンドで書く。設定は [設定の一覧](admin/configuration.md)、コマンドは [コマンドの一覧](admin/cli.md) に必ず載せる |
| `docs/dev/` | 開発者ガイド | コードの場所・テストの場所・決まりごと |
| `docs/design/` | 設計書 | 仕組みと理由。番号付きの章（コードのコメントやテストから「extensions.md 6 章」のように参照される） |
| `docs/research/` | 調査・計測 | 書いた時点の記録。原則として後から書き換えない |

新しい機能を入れたときにどの文書を直すかは、[文書の書き方と更新の手順](dev/docs-guide.md) にまとめています。`tests/test_docs.py` が、リンク切れと、設定・コマンドの載せ忘れを確かめます。
