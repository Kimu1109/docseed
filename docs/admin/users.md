# ユーザーとログイン

ユーザーの管理は管理画面（左のメニューの「管理」）で行います。管理画面は LAN・Tailscale の中からだけ開けます（[インターネットに公開する](exposure.md)）。

利用者が自分で行うログインの設定（パスキー・確認コード・外部アカウントの連携）は [利用者ガイドのログインと安全](../user/login.md) を案内してください。

## ユーザーを足す・変える

管理画面の「ユーザーを追加」で、ユーザー名・表示名・初期パスワード・ロール（一般 / 管理者）を決めます。初期パスワードは本人に伝え、ログイン後に「設定」→「パスワード」で変えてもらいます。

「ユーザー」の表の各行で次ができます。

| 操作 | 内容 |
|---|---|
| 無効にする / 有効にする | 無効にするとログインできなくなります（ファイルは残ります） |
| 管理者にする / 一般にする | ロールを変える |
| 再設定 | パスワードを決め直す |
| ログイン方法をリセット | パスキー・確認コード・外部アカウントの連携を消し、すべての端末をログアウトして、仮のパスワードを発行します（この画面を離れると二度と表示されません） |
| 使用量・上限 | 容量の上限（[下](#容量の上限とゴミ箱)） |

最初の管理者はコマンドで作ります（[導入](install.md)）。

```bash
docker compose exec api docseed create-admin --username <名前>
```

## 2 段階認証を必須にする

管理画面の「ログイン」の「パスワードでログインする人に 2 段階認証（確認コード）を必須にする」。未設定のユーザーは、確認コードを設定するまでほかの画面を使えません（パスキーや外部アカウントでログインした人は対象外）。インターネットに公開するなら有効にしてください。

## 管理者自身がログインできなくなったとき

Pi で次を実行します。ログイン方法を消し、仮のパスワードを表示します。すべての端末をログアウトし、API トークンも無効にします。

```bash
docker compose exec api docseed reset-auth --username <名前>
```

## パスキーを使うための条件

- **`DOCSEED_HOST` の名前（ドメイン名）で、信頼された証明書の HTTPS で開く**必要があります（パスキーは名前に結び付くため、IP アドレスで開くと使えません。内部 CA の証明書は、端末に CA 証明書を入れていれば使えます）。[HTTPS の証明書](https.md) の `file`・`tailscale`・`acme_dns` が便利です
- パスキーは `DOCSEED_HOST` の最初の名前（`DOCSEED_RP_ID` で変更可）に登録されます。**この名前を後から変えると、登録済みのパスキーはすべて使えなくなります**（管理画面に警告が出ます）
- `DOCSEED_HTTPS_PORT` を 443 以外にしている場合も、そのポート付きの URL で開けば使えます

## Google などでログインする（OIDC）

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「API とサービス」→「OAuth 同意画面」で種類を「外部」にして、範囲（スコープ）は `openid`・`email`・`profile` だけにします
2. 公開ステータスが「テスト」のままなら、使う人の Google アカウントを「テストユーザー」に登録します（最大 100 人）。この 3 つの範囲だけなら「本番環境」に公開することもできます（Google の規則は変わることがあるので、画面の案内に従ってください）
3. 「認証情報」→「OAuth クライアント ID を作成」→ 種類「ウェブ アプリケーション」。「承認済みのリダイレクト URI」に `https://<DOCSEED_HOST>[:<DOCSEED_HTTPS_PORT>]/auth/oidc/google/callback` を登録します。Google は HTTPS と公開されたドメイン名（`*.ts.net` や自分のドメイン）を求めるので、`.local` や IP アドレスでは使えません（Pi がインターネットから届く必要はありません）
4. `.env` に書いて `docker compose up -d` で api を作り直します

```bash
DOCSEED_OIDC_PROVIDERS=google
DOCSEED_OIDC_GOOGLE_ISSUER=https://accounts.google.com
DOCSEED_OIDC_GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
DOCSEED_OIDC_GOOGLE_CLIENT_SECRET=xxxxxxxx
DOCSEED_OIDC_GOOGLE_LABEL=Google
```

5. 各ユーザーが一度パスワードなどでログインし、「セキュリティ」→「Google と連携」で自分のアカウントを結び付けます。管理画面で、連携できるメールアドレスのドメインを絞れます（例 `example.com`）

Pocket ID・Authelia・Keycloak など、ほかの OIDC の提供者も同じ書き方で足せます（`DOCSEED_OIDC_PROVIDERS=google,pocketid` と、`DOCSEED_OIDC_POCKETID_ISSUER` など）。

## 容量の上限とゴミ箱

- 管理画面の「ユーザー」で **容量の上限** を決められます（下の「容量の上限の全体の既定」と、ユーザーごとの値。ユーザーの欄を空にすると全体の既定、0 なら上限なし）。上限を超えるアップロード・新しい版・コピーは断ります
- 数えるのは、自分のフォルダにあるファイル・ゴミ箱の中・過去の版です。共有したフォルダや受け取り用のリンクに置かれたファイルは、フォルダの持ち主の分になります
- **ゴミ箱に残す日数** は各自が設定で 7〜365 日から選べます。選んでいない人は `DOCSEED_TRASH_RETENTION_DAYS`（既定 30）
- **過去の版** は 1 ファイルにつき `DOCSEED_VERSIONS_KEEP`（既定 10）件まで。`0` にすると残しません（減らしたときは、次の毎日の片付けで多い分を消します）。過去の版は画面の「使用量」に含めますが、検索の対象にはなりません
- 1 ファイルの大きさの上限は `DOCSEED_MAX_UPLOAD_MB`（既定 1024）
