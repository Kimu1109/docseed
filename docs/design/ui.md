# 画面設計

[設計書](../design.md) の Web UI 部分の詳細。

## 1. 方針

| 項目 | 内容 |
|---|---|
| 方式 | サーバー側で HTML を生成（Jinja2）＋ htmx による部分更新。ビルド工程の要る SPA にはしない |
| 理由 | Pi 5 でビルド不要・軽量。API と同じ Python コードベースで完結する |
| CSS | 自前の CSS 1 ファイル（`static/app.css`）。CDN は使わない（オフラインでも動くように） |
| JavaScript | htmx（同梱）と小さなスクリプト（`static/app.js`: ダイアログ・アップロード・お知らせ）。PDF はブラウザ内蔵のビューアで表示 |
| 対応端末 | PC とスマートフォンのブラウザ（レスポンシブ）。スマホからの写真アップロードを想定 |
| 言語 | 日本語のみ（文言はテンプレートにまとめ、将来の多言語化に備える） |
| テーマ | ライトのみ（Phase 1 の決定。ダークは必要になったら追加） |

### 1.1 デザインの方針（Phase 1 で決定）

- **角ばった、シンプルなライトトーン**。角丸と影は使わない。区切りは 1px の罫線、強調は 2px の線と藍色（#2C4A7A）だけ。
- 背景は少し青みのある冷たい白（#F5F6F4）、面は白、文字は #1D2321、罫線は #D3D9D6。
- 書体は BIZ UDPゴシック（なければ IBM Plex Sans JP → Noto Sans JP）。サーバーはオフラインで動くため Web フォントは配信しない。
- 目立たせる要素は 1 つだけ: ファイル一覧の左端の **種類ごとの色の縦帯**（フォルダ = 藍、PDF = 赤、画像 = 緑、表計算 = 黄緑、スライド = 橙 など）。
- 色はすべて `src/docseed/web/static/app.css` の `:root` にまとめている（規則以外の場所に色を直接書かない。QR コードの白だけは読み取りのためそのまま）。
- **ダークモード**（実装で追加）: 同じ色のトークンを暗い色で定義し直す。既定は端末の設定（`prefers-color-scheme`）に合わせ、設定画面の「画面の色」で「ライト」「ダーク」に固定できる（`user_prefs` の `theme` = auto / light / dark。サーバーが `<html data-theme>` と `<meta name="color-scheme">` を出すので、読み込み時にちらつかない）。暗い背景では、藍・種類の縦帯の色を明るめにする。ログイン画面などログイン前の画面は端末の設定に合わせる。
- アイコンは Phase 6 で Material Symbols（Sharp）の SVG スプライトにする（[拡張機能](extensions.md) 3 章）。下の画面の図の絵文字は仮の表記。

画面から API を直接呼ぶのではなく、画面用のルート（`/`, `/f/{id}` など）が HTML の断片を返す。データの処理は API と同じサービス層の関数を使う。

画面のルートは `src/docseed/web/views/` に画面ごとに分ける（`login`・`files`・`webclips`・`share`・`documents`・`organize`（お気に入り・タグ・却下した候補）・`search`・`trash`・`settings`・`admin`）。共通のテンプレート・ルーター・`base_context`・お知らせは `web/common.py`、`web/routes.py` は views を読み込む順を決めて共通の名前を出し直すだけ。

## 3. 共通レイアウト

```
┌──────────────────────────────────────────────────────────────┐
│ docseed   [🔍 検索…                                 ]  [⬆]  [👤] │  ← ヘッダ（検索窓は常に表示）
├────────────┬─────────────────────────────────────────────────┤
│ マイファイル  │                                                 │
│ 共有された   │              メイン領域                          │
│ ゴミ箱       │                                                 │
│ ─────      │                                                 │
│ 処理中: 3   │                                                 │
│ 使用量 12GB │                                                 │
│ (管理)      │                                                 │
└────────────┴─────────────────────────────────────────────────┘
```

- スマホ（幅 860px 以下）は下の「3.1 スマホ用の画面」のとおり、PC とは別の組み立てにする。

### 3.1 スマホ用の画面（実装で追加）

HTML は PC と同じテンプレートを使い、スマホだけの部品（`.m-only`・`.m-meta`・`.tabbar`・`.fab` など）を PC では隠し、PC だけの部品（`.pc-only`）をスマホでは隠す。指で押す所は高さ 40px 以上、入力欄は 16px（iOS が拡大しないように）。`viewport-fit=cover` と `env(safe-area-inset-bottom)` で画面下の余白に合わせる。

- 上のバーはロゴとユーザーのメニュー（アイコンだけ）。検索欄とメニューボタンは出さない。
- 画面下に 5 つのタブ: ファイル・お気に入り・検索・共有・メニュー。「メニュー」はサイドバー（タグ・ゴミ箱・管理・設定・使用量）を左からの引き出しとして開く（後ろを暗くし、外側・Esc・リンクで閉じる）。管理者に警告があればタブに赤い印を出す。
- ファイル一覧は端まで広げた 1 列。表の見出しは隠し、更新日・サイズ・状態（「処理済み」以外）は名前の下に小さく出す。並べ替えは一覧の上のボタン（名前・更新日・サイズ）。
- フォルダの操作（お気に入り・ZIP・共有）はアイコンだけのボタン。追加は右下の「＋」から、下から出るメニューで「ファイルをアップロード・カメラで撮ってアップロード（`capture="environment"`）・新しいフォルダ・URL を追加」を選ぶ。
- 行の「…」は下から出るメニューにし、先頭にファイル名、「開く」「選択」を足す。
- 選択はタッチ向けにする: 行の長押し（約 0.45 秒）か、メニューの「選択」で始め、選択中は行（名前を含む）のタップで足す・外す。選択していないときの行のタップは開く。選択中は下のタブの位置に操作のバーを出す（横に送って全部押せる）。タッチではドラッグでの移動は使わない（長押しと重なるため、`draggable` を外す）。
- ダイアログは下から出るシートにする。
- 文書の画面: 名前は折り返して全部出し、その下にボタン（ダウンロードだけ文字付き）。PDF は「全画面で開く」を足す（iOS の埋め込み表示は 1 ページ目しか出ないことがあるため）。
- 検索: 絞り込みは「絞り込み」ボタンで開く（使っている絞り込みの数をボタンに出す）。
- 設定・管理などの表は横に送れるようにし、画面全体は横にはみ出させない。
- 「処理中: N」は OCR・埋め込み待ちの自分の文書数。クリックで一覧へ。

## 4. 各画面

### S02 ファイル一覧

```
マイファイル > 経理 > 2026                          [＋ フォルダ] [⬆ アップロード] [共有]
┌──┬───────────────────────────┬──────────┬────────┬──────────────┐
│  │ 名前 ▲                     │ 更新日     │ サイズ   │ 状態           │
├──┼───────────────────────────┼──────────┼────────┼──────────────┤
│📁│ 10月                       │ 11/07     │ —      │              │
│🖼│ 見積書_2026-10.pdf  #経理   │ 11/07     │ 471KB  │ ✓ 検索可       │
│🖼│ 領収書.jpg                  │ 11/07     │ 1.2MB  │ ⏳ OCR中 2/3   │
│🖼│ 古い契約書.pdf              │ 10/30     │ 8.4MB  │ ⚠ 一部失敗     │
└──┴───────────────────────────┴──────────┴────────┴──────────────┘
```

- 一覧表示 / サムネイル表示の切り替え。
- 並べ替え: 名前・更新日・サイズ。
- ページ送り: 1 ページに 100 項目（フォルダが先、続いて文書）。項目が多いフォルダでは一覧の下に「前へ / 次へ」と「N / M ページ（a〜b 件目 / 全 n 件）」を出す（`?page=`、並べ方と一緒に URL に残す）。範囲外のページは最後のページを出す。名前の変更・移動・削除などの後の描き直しは、今見ているページと並べ方（`HX-Current-URL`）のまま。URL の取り込み中の行と「自動で移動した文書」は 1 ページ目だけに出す。
- 複数選択して: 移動、コピー、ダウンロード（ZIP）、削除、タグ付け。
- ドラッグ＆ドロップでアップロード（フォルダごとも可）。各ファイルの送信進捗を表示。フォルダの行の上で離すと、そのフォルダへアップロードする。
- 選択と移動はエクスプローラーと同じ操作感にする（編集できるフォルダのみ）。
  - 行のクリックで選択、Ctrl（⌘）+クリックで追加・解除、Shift+クリックで範囲選択、ダブルクリックで開く。名前のリンクのクリックは今までどおり開く。空いたところのクリックで選択を外す。
  - 選んだ行をフォルダの行・パンくず・サイドの「マイファイル」へドラッグすると移動する（`POST /x/items/move`、`item=folder:ID` / `item=document:ID` を複数）。つかんだ行が選択外なら、その行だけを選び直す。
  - キー: Ctrl+A（すべて選択）、Esc（解除）、↑↓（Shift で範囲）、Enter（開く）、F2（名前を変更）、Delete（ゴミ箱へ、`POST /x/items/delete`）。
  - 選択中は画面下に「N 件を選択中 / 移動 / タグ / 再処理 / 要約とタグをやり直す / ゴミ箱に移動 / 選択を解除」のバーを出す（スマホなどドラッグできない環境向け）。
  - タグ・再処理・要約とタグのやり直しはファイルだけが対象（フォルダは中身に及ばない。フォルダだけを選んでいるときは押せない）。一度に 500 件まで。権限が無い・処理中などでできなかったものは件数と最初の理由をお知らせに出し、ほかは続ける。
    - タグ（`POST /x/items/tags`、`add` / `remove` はカンマ区切り）: 付けるタグを足し、外すタグを除く。ほかのタグはそのまま。
    - 再処理（`POST /x/items/reprocess`）: 文字の読み取りをやり直す。処理待ち・処理中のものは飛ばす。
    - 要約とタグをやり直す（`POST /x/items/redo`。整理の補助か LLM が有効なときだけ出す）: 文書の画面の「要約とタグをやり直す」と同じ（手で直した要約も自動の要約に戻す）。要約のジョブは priority 15（1 件ずつ頼んだもの（5）より後）。
  - 一部だけ失敗した場合は、できた分を処理して「N 件を移動しました（M 件はできませんでした: 理由）」と知らせる。
- 状態の列は SSE（`/api/v1/events`）で自動更新する。
- 行のメニュー: 開く、ダウンロード、名前変更、移動、共有、削除。
- 他人から共有されたフォルダでは、ヘッダに「〇〇さんのフォルダ（閲覧のみ）」のように自分のロールを表示する。

### S03 文書詳細

```
← 経理 / 2026                                         [ダウンロード] [共有] [⋯]
見積書_2026-10.pdf                          #経理 [+タグ]
┌──────────────────────────────────┬───────────────────────────────┐
│                                  │ [情報] [テキスト] [OCR]          │
│        プレビュー                  │                               │
│   （PDF: pdf.js / 画像: <img>）     │ ページ 2                       │
│                                  │ お手数ですが下記の振込先まで…      │
│      ◀  2 / 3  ▶                  │                               │
└──────────────────────────────────┴───────────────────────────────┘
```

- プレビュー: PDF と画像はブラウザ内で表示。それ以外は種類のアイコンとダウンロードボタン。
- 検索結果から開いた場合は該当ページを開き、テキストタブで検索語をハイライトする。
- 「テキスト」タブ: ページごとの抽出テキスト。コピー可能。`source`（テキスト層 / OCR）と OCR の信頼度を表示。
- 「OCR」タブ: ページ画像の上に認識した行の枠を重ねて表示（信頼度が低い行は色を変える）。OCR の誤りを確認するため。
- 「情報」タブ: サイズ、種類、SHA-256、作成者、日時、処理状況・警告、この文書の共有リンク一覧。
- メニュー（⋯）: 名前変更、移動、コピー、再処理（OCR を強制）、削除。
- **関連する文書**（実装で追加）: 処理が終わった文書では、横の欄に内容が似ている文書を 5 件まで出す（`GET /x/d/{id}/related` を開いた後に読み込む。似ている文書が無ければ欄ごと出さない）。見られる文書だけで、同じ中身のコピーは出さない。
- **過去の版**（実装で追加）: 同じ名前で上書きした・新しい版をアップロードした・Web クリップを再取得したときの、前の中身の一覧（追加した日時・サイズ・追加した人・置き換えた日時）。ダウンロードは閲覧できる人なら誰でも、「この版に戻す」（`POST /d/{id}/versions/{vid}/restore`）と「削除」（`POST /d/{id}/versions/{vid}/delete`）は編集できる人だけ。「新しい版をアップロード」（`POST /d/{id}/versions`、Web クリップには出さない）で、名前・フォルダ・タグを変えずに中身だけを替える。情報の欄に「今の版」（その中身を追加した日時と、過去の版の件数）を出す。

- 検索モードの切り替え（すべて / 意味 / キーワード）は「すべて ▾」から。

- `notices`（2 文字以下の語の制約など）は結果の上に小さく表示。
- 絞り込みに「撮影日（から・まで）」（`taken_from` / `taken_to` → `taken:から..まで`）を追加（実装で追加）。撮影日のある結果には撮影日時を出す。検索語が無くても、種類・タグ・日付・撮影日のどれかで絞れば当てはまるファイルを一覧にする（フォルダだけでは出さない）。

```
「経理」を共有
─ ユーザー ─────────────────────────────
  [ユーザーを追加 ▾] [閲覧 ▾] [追加]
  👤 Hanako   編集できる ▾   [削除]
─ リンク ───────────────────────────────
  [＋ リンクを作成]
  https://docseed.local/s/Xc9…  閲覧  期限 11/14  パスワードあり  3回DL  [コピー] [編集] [無効化]
```

- 文書の場合は「ユーザー」欄を出さない（権限はフォルダ単位のため）。代わりに「この文書は『経理』フォルダの権限に従います」と表示する。
- リンク作成時の項目: 権限（閲覧 / アップロードのみ）、期限（1 日・7 日・30 日・日付指定・無期限）、パスワード、ダウンロード回数上限。

### S07 ゴミ箱

- 削除単位（フォルダ単位・文書単位）で一覧。元の場所、削除した人、削除日、完全削除までの残り日数。
- 保持日数は利用者ごと（設定の「容量とゴミ箱」で選ぶ。実装で追加）。画面の上に今の日数を出す。
- 復元、完全削除、ゴミ箱を空にする（確認ダイアログあり）。
- 名前を押すと中身を確かめられる（消してよいかを判断するため。実装で追加）。
  - 文書（`/trash/document/{id}`）: 文書の画面と同じプレビュー（PDF・画像・音声・動画・テキスト）と取り出したテキスト、元の場所・削除日・サイズ、ダウンロード・元に戻す・完全に削除。編集の操作は出さない。
  - フォルダ（`/trash/folder/{id}`）: 一緒に削除されたファイルの一覧（フォルダの中の場所付き）。各ファイルを押すと上のプレビューを開く。フォルダごと元に戻す・完全に削除。
  - 見られるのはゴミ箱と同じく持ち主だけ。プレビューの画面から戻すと戻した先を開き、完全に削除するとゴミ箱に戻る。

### S09 管理

| タブ | 内容 |
|---|---|
| 確認が必要な項目 | 警告の一覧（Phase 5）。worker の停止、失敗したジョブ、SSD の空き（10% / 5%）、バックアップの遅れ・失敗、CPU 温度。error / warning の件数は左メニューの「管理」に赤いバッジで出す（管理者のみ） |
| システム | CPU 温度・負荷、メモリ、ディスク（SSD）使用量、DB サイズ、文書・チャンク数、worker の最終応答時刻、モデル名、パイプラインの版 |
| バックアップ | DB スナップショットの最終作成日時、restic の最終結果（日時・成否・スナップショット ID） |
| ジョブ | 状態別の件数、失敗ジョブの一覧とエラー、再実行、一括再処理 |
| ユーザー | 作成、ロール変更、無効化、パスワード再設定 |
| 監査ログ | 絞り込み（ユーザー・操作・期間） |

### S10 共有リンクの公開ページ

- ログイン画面やアプリのメニューは出さない。docseed のロゴ、共有した人の表示名、期限だけを表示。
- 文書: プレビューとダウンロードボタン。
- フォルダ: 一覧（パンくずで配下へ移動）、プレビュー、個別・一括ダウンロード。
- アップロードのみ: ドラッグ＆ドロップの受付画面と、自分が送ったファイル名の一覧（そのブラウザのセッション内のみ）。
- パスワード付きはパスワード入力画面を先に表示。

### S11 お気に入り・最近開いたファイル（実装で追加）

- サイドのメニューの「お気に入り」（マイファイルの次）。上に **お気に入り**（入れた新しい順。文書とフォルダ）、下に **最近開いたファイル**（文書の画面を開いた新しい順に 20 件、「記録を消す」）。
- お気に入りは、文書の画面の題の横と、フォルダの画面の操作の並びの「☆お気に入り」で入れる・外す（`POST /x/favorite`、htmx でボタンだけを差し替える。入っていれば色を変え `aria-pressed="true"`）。一覧では、お気に入りの名前の横に ☆ の印を出す。
- 出すのは今見られるものだけ（ゴミ箱の中・共有をやめられたものは出さない）。完全に削除されたものは、記録も消す。
- 最近開いたファイルは、利用者ごとに新しい 50 件だけ残す。API での取得・ダウンロードは数えない。

### S12 ヘルプ（実装で追加）

リポジトリの `docs/` の Markdown を、そのまま画面で読めるようにする（`helpdocs.py`・`web/views/help.py`）。GitHub で読む文書と画面のヘルプを 1 つの元にして、二重に書かない。

- URL: `docs/README.md` → `/help`、`docs/user/README.md` → `/help/user`、`docs/user/files.md` → `/help/user/files`。サイドの「ヘルプ」（`g` → `h`）は `/help/user` を開く
- 変換は markdown-it-py（CommonMark・表・取り消し線・チェックリスト）。**生の HTML は出さない**（`html=False`。文字として出す）。`javascript:` などのリンクも出さない
- 相対リンク（`../admin/https.md#…`）は画面の URL（`/help/admin/https#…`）に書き換える。`docs/` の外（ルートの README・ソース）を指すリンクは、リンクにしない。外のサイトへのリンクは新しいタブで開く（`rel="noopener noreferrer"`）
- 見出しの id は GitHub と同じ形（`helpdocs.slug`。`tests/test_docs.py` も同じ関数でリンクを確かめる）
- 上のタブ: 利用者ガイド（全員）・管理者ガイド・開発者ガイド・設計書・文書の地図（管理者だけ）。タブに出さなくても、リンクから開くことは誰でもできる（文書はリポジトリで公開しているものと同じで、秘密は書かない）
- `docs/dev/templates/`（ひな形）は出さない
- 確認コードの設定を求められている間も読める（`deps.SETUP_ALLOWED_PREFIXES`）
- イメージには wheel の `docseed/_docs` として入る（`pyproject.toml` の force-include、`docker/Dockerfile` の `COPY docs`）。開発中はリポジトリの `docs/` を読む
- 管理画面の説明文から、関係するヘルプのページへ張る（バックアップ・通知・導入）

### S04 への追加: 検索の履歴・保存した検索（実装で追加）

- 画面で検索すると、条件（検索語・検索方法・絞り込み）を **最近の検索** に残す（同じ条件は 1 件にまとめ、新しい 30 件。ページ送りと API の `/search` は残さない）。
- 結果の上の「この検索を保存」（名前は省略すると検索語）で **保存した検索** に残す（100 件まで）。
- 検索語も絞り込みも無い検索画面に、保存した検索（名前順。行のメニューで名前の変更・消す）と最近の検索（× で 1 件消す、「履歴をすべて消す」）を並べる。押すとその条件で検索する。

## 5. アップロードの挙動

- ファイル選択・ドラッグ＆ドロップ・スマホのカメラ（`<input type="file" accept="image/*,application/pdf" capture>`）に対応。
- 同時送信は 2 ファイルまで。送信中はファイルごとの進捗バーを表示し、ページを離れようとしたら確認する。
- 同名がある場合の既定は「別名で保存」。設定でアップロード時に毎回確認するようにも変えられる。

## 6. アクセシビリティ・その他

- キーボード操作（実装で追加・`?` で一覧のダイアログ、ユーザーのメニューの「キーボード操作」からも開ける。文字の入力中・ダイアログを開いているときは効かない）:
  - どこでも: `/` 検索欄へ、`?` 一覧、`g` に続けて `m`（マイファイル）・`f`（お気に入り）・`s`（共有されたフォルダ）・`t`（タグ）・`d`（ゴミ箱）・`a`（管理、管理者だけ）で画面を移る（1.5 秒以内）、`s` で今のファイル・フォルダをお気に入りに入れる・外す。
  - ファイルの一覧: `j` `k`（`↓` `↑` と同じ）で移動、`Enter` で開く（ここまでは閲覧だけのフォルダでも使える）。編集できるフォルダでは、`Shift`+移動で範囲、`x` でカーソルの行を選択に足す・外す、`Ctrl`+`A`、`Esc`、`F2`、`Delete`、`u`（アップロード）、`n`（新しいフォルダ）。
  - 検索結果: `j` `k` で結果の名前に移り、`Enter` で開く。
- 画像には代替テキスト（ファイル名）を付ける。色だけで状態を表さない（アイコン＋文字）。
- 日時は利用者のブラウザのタイムゾーンで表示（既定 Asia/Tokyo）。

## タグの管理・却下した候補（実装で追加）

- **タグ**（`/tags`、サイドの「タグ」）: 自分のファイル（自分が持ち主のフォルダにある文書）に付いているタグと件数の一覧（件数の多い順、ゴミ箱の中は数えない）。タグを押すと、そのタグが付いたファイル（新しい 200 件）を出す（検索はキーワードが要るため、この画面で出す）。
  - 名前の変更（`POST /tags/rename`、`old`・`new`）: 自分のファイルに付いたそのタグを新しい名前に付け替える（ゴミ箱の中も）。既にある名前にすると統合になる。タグの名前の表（`tags`）は利用者で共有なので、ほかの人のファイルのタグは変えない。大文字・小文字だけの変更は、ほかの人が使っていないときだけ名前を書き換える。
  - 外す（`POST /tags/delete`、`name`）: 自分のファイルからそのタグを外す（ファイルは消さない）。どの文書にも付いていないタグの名前は片付ける。
- **却下した候補**（`/suggestions/rejected`、`?doc=` で 1 文書に絞る。設定の「整理の補助」と、文書の画面の「却下した候補 N 件」から開く）: 自分のファイルで却下したフォルダ・タグの候補の一覧。「取り消す」（`POST /suggestions/{id}/unreject`）で候補に戻す。もうそのフォルダにある・そのタグが付いているときは、候補に戻さず却下の記録だけを消す（今後また候補に出せる）。
