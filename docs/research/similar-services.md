## 0. 要約

- docseed の独自性は、**日本語の文書を手元の機械だけで、OCR・キーワード検索・意味検索まで一体で扱う**点、**Raspberry Pi 5 に合わせて軽く作っている**点、**フォルダ単位の権限・共有リンク・受け取り箱を備えた小さな共有サーバー**である。
- 「文書管理（OCR と検索）」だけなら **Paperless-ngx** が成熟していて、機能と周辺のエコシステムが厚い。「ファイルの同期と共有」まで含めるなら **Nextcloud** や **Seafile** が候補になるが、どちらも docseed の設計書が述べる通り Pi 5 では重めになりやすい。
- 「Web クリップ＋AI の整理（タグ・要約）」は **Karakeep** と重なる。ただしファイルの共有や版の管理は対象外。
- 商用のクラウド（Google Drive・Dropbox・Box）は AI 検索が使いやすい一方、データが外に出る。docseed の「外部クラウドに依存しない」方針とは反対の立場。

## 1. 比較対象

| # | サービス | 種類 | 主な用途 | 自前運用 |
|---|---|---|---|---|
| A | **docseed**（本プロジェクト） | 文書サーバー | 保存・共有・OCR・ハイブリッド検索・URL の取り込み・要約 | Docker（Pi 5） |
| B | **Paperless-ngx** | 文書管理 | スキャン文書の OCR・タグ・検索・ワークフロー | Docker |
| C | **Paperless-AI**（Paperless-ngx 用の拡張） | 文書の AI 整理 | 分類・タグ付け・意味検索（RAG） | Docker、Ollama など |
| D | **Nextcloud**（＋ Findling など） | ファイル同期・共有の基盤 | 同期クライアント・共有・アプリで検索を追加 | Docker / 直接インストール |
| E | **Seafile** | ファイル同期・共有 | 同期・共有・ライブラリ単位の権限、13.0 で AI 検索 | Docker |
| F | **Karakeep**（旧 Hoarder） | ブックマーク・メモ | Web・画像・メモの保存、OCR、AI によるタグ・要約 | Docker |
| G | **Docspell** | 文書管理 | OCR・分類・自然言語処理による整理 | Docker、Java |
| H | **Google Drive / Dropbox（Dash）/ Box AI** | 商用クラウド | 同期・共有・AI による検索や質問応答 | なし（SaaS） |

## 4. 強みと弱みの整理

### docseed

- **強み**
  - 日本語の意味検索（ruri-v3）と日本語 OCR（PP-OCRv6）を、Pi 5 で動く形に最適化している
  - フォルダ権限、共有リンク、受け取り箱、パスキー・OIDC、Tailscale・Cloudflare Tunnel への対応を一つの小さなサーバーにまとめている
  - 外部に送らない方針が一貫している
- **弱み**
  - 同期クライアントがない（スマホやデスクトップからの同期は対象外）
  - 版管理がない
  - 利用者・事例がまだ少なく、他人の環境で検証された度合いが低い
  - 「Paperless-ngx の文書ワークフロー（ルール・相関先・ASN など）」のような細かい整理機能は持たない

### Paperless-ngx

- **強み**: 文書管理の定番。OCR・タグ・検索・ワークフローが成熟し、情報が多い。3.0 で AI 機能が入ったと報じられている。
- **弱み**: 共有の仕組みは限定的。意味検索は 3.0 の AI 機能に依存し、既定ではない（確認が必要）。大きなスキャンの OCR は Pi では遅い。
- **docseed との差**: docseed は「共有サーバー」と「日本語の意味検索」を前面に出す。Paperless は「文書の分類と整理」に強い。

### Paperless-AI

- **強み**: Ollama などのローカル LLM で意味検索と RAG チャットができる。MIT ライセンスと報じられている。
- **弱み**: Paperless-ngx の追加機能で、単体では動かない。3.0 の AI 機能と役割が重なる。
- **docseed との差**: docseed は埋め込みを標準で持ち、外部 LLM に依存しない。

### Nextcloud（＋ Findling など）

- **強み**: 同期クライアント・共有・ユーザー管理の基盤として最も成熟し、エコシステムが大きい。Findling は OCR と意味検索を備える。
- **弱み**: Pi 5 では重い（設計書の判断）。検索はアプリの組み合わせに依存し、アプリの互換性で止まることがある（フォーラムの報告）。
- **docseed との差**: 同期の有無と機能の広さで Nextcloud が勝つ。Pi 上の軽さと、日本語の検索を一体で作ったことは docseed の強み。

### Seafile

- **強み**: 同期・共有が軽快で、ライブラリ単位の権限が分かりやすい。13.0 で AI 検索が入ったと報じられている。
- **弱み**: 13.0 で Community Edition の形態が変わり（バイナリ配布が終わり Docker 推奨）、AI 検索と全文検索の機能が CE でどこまで使えるかは未確認。
- **docseed との差**: Seafile は同期が本職。docseed は OCR と検索の深さで差別化する。

### Karakeep

- **強み**: ブックマーク・メモ・画像をまとめ、OCR・AI によるタグ付け・要約・全文検索が揃う。Web クリップの体験がよい。
- **弱み**: ファイルの共有サーバーではない。PDF や Office 文書の扱いは主な対象ではない。公式の最低ハードウェア要件は未確認。
- **docseed との差**: 「Web の情報を整理する」Karakeep と「文書を共有・検索する」docseed は、重なる部分（URL 取り込み・要約）と分かれる部分（共有・Office）がある。

### Docspell

- **強み**: OCR・分類・自然言語処理を備えた文書管理。GPL でライセンス上の制限がない。Pi 向けの導入スクリプトがある。
- **弱み**: 導入の評判が割れている。Java と Solr を要し、Pi 5 での軽さは未確認。日本語の検索精度は未確認。
- **docseed との差**: Docspell は「文書の整理」に寄り、意味検索と共有の仕組みは限定的（確認が必要）。

### 商用クラウド（Google Drive・Dropbox・Box）

- **強み**: 同期・共有・版管理・AI 検索が一通り揃い、運用がほぼ不要。
- **弱み**: データが外に出る。AI 検索は有料プランや別料金のアドオンが要る場合がある（価格は各社の公式ページで確認が必要）。
- **docseed との差**: docseed は「自分のデータを手元に置く」用途に限る。商用は「手間をかけずに使う」用途。

## 5. docseed の今後への示唆

1. **Paperless-ngx 3.0 の AI 機能との比較**を実機で確かめる価値が高い。同じ文書セットで、OCR の精度、日本語の検索結果、速さを比べると、docseed の立ち位置がはっきりする。
2. **版管理と同期は対象外のままでよいか**を判断する。利用者が同期クライアントを求めるなら、Nextcloud か Seafile との併用を案内する方が現実的。
3. **Karakeep との境界**（URL の取り込み・要約）を決める。どちらにも同じ機能があるので、docseed の Web クリップは「文書として保存して検索する」ことに絞ると差が出る。
4. **未確認の項目を埋める**: Seafile CE の全文検索、Karakeep の Pi での動作、Paperless-ngx 3.x の意味検索の既定値、各サービスの日本語の検索精度。

## 6. 確度と調査の限界

- 各サービスの一次情報（公式のリリースノート・ドキュメント）は、ほとんど確認できていない。多くは二次情報（ニュース、レビュー、コミュニティの投稿）に基づく。
- 特に次の情報は**未確認**で、判断の前に一次情報で確かめること
  - Paperless-ngx 3.x の AI と意味検索の既定値・対応範囲
  - Seafile CE の 13.0 での AI 検索・全文検索の範囲
  - Karakeep の公式の最低要件と OCR の仕組み（ローカルか外部か）
  - 商用クラウドの現行の価格
  - 各サービスのライセンス（今回は確認していない）
- 日本語の検索精度の比較は、どのサービスも確認していない。docseed の強みを主張するなら、実際の日本語の文書で比べる必要がある。
- docseed の機能の記述は、リポジトリの README と `docs/design.md` に基づく。
